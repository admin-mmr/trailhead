## Tech Stack

### Frontend / App
- **Framework**: Next.js 14.2.5, App Router, TypeScript, Tailwind CSS
- **Repo path**: `mmr-webapp/`
- **Local dev**: `npm run dev` → `http://localhost:3000`
- **CRITICAL**: Config file is `next.config.mjs` (NOT `.ts`) — Next.js 14 does not support TypeScript config. Never rename it.
- **CRITICAL**: `postcss.config.js` must exist — Tailwind will not compile without it.
- **Node version**: Use Node 18 or 20 LTS (not v25+)

### Hosting
- **Azure Static Web Apps** (free tier) — hosts Next.js + API routes as Azure Functions
- **Auto-deploy**: GitHub `main` branch → Azure via GitHub Actions
- **Legacy prototype**: Azure Blob Storage static website (`mmrunnersstorage` / `$web` container)

### Database
- **Azure Database for MySQL Flexible Server**
  - Host: `mmr-mysql.mysql.database.azure.com`
  - Database: `mmrdb`
  - User: `mmradmin`
  - SSL required (`--ssl-mode=REQUIRED`)
- **Migration script**: `mmr-webapp/db/mmr_migration_v1.sql`
- **Source of truth**: MySQL. Google Sheet "Membership Master" is a downstream read-only nightly export for volunteers.
- **Current state**: Migration in progress. ~600 member rows need one-time import from Google Sheet.

### Storage
- **Azure Blob Storage**: account `mmrunnersstorage`
  - Container `media` — payment proof screenshots, blog images
  - Container `$web` — legacy static prototype

### Email
- **Azure Communication Services** (`mmr-comms`) — OTP codes, membership confirmation, password reset

### Authentication
- **Email OTP** (live): 6-digit code, 24h expiry, sent via Azure Communication Services
- **Password** (planned): bcrypt/argon2id hashed; `password_reset_tokens` table for forgot-password flow
- **Social login** (planned): Google, Microsoft (personal accounts), Apple — via NextAuth.js, all free
- **Login key**: always the member's email address
- **Session**: JWT cookie, 7-day expiry, `jose` library (edge-compatible)
- **Middleware**: `middleware.ts` protects `/portal/*` and `/api/members/*`

### Payments
- **NO Stripe** — Zelle and Venmo only (zero transaction cost for nonprofit)
- Zelle: `treasurer@mmrunners.org`
- Venmo: `@MMRunners`
- QR codes: `public/images/qr-zelle.png`, `public/images/qr-venmo.png`

### Internationalization
- English (EN) + Simplified Chinese (中文/ZH)
- All strings in `lib/i18n/translations.ts`
- `LanguageProvider` context + `useLang()` hook throughout
- Admin pages: English only

## Key Design Decisions — Do Not Reverse Without Asking

1. **No Stripe** — Zelle/Venmo only. Non-negotiable for nonprofit cost reasons.
2. **Pending status is DERIVED** — never stored on `members.Status`. Query `payment_events` at display time.
3. **MemberID format is `A0001`** (sequential, 4-digit zero-padded). Generated by `generate_member_id()` stored procedure. The old brief said `MMR-YYYY-NNNN` — that is wrong. Production data uses `A0001`.
4. **Email is always the login key** — true for OTP, password, and all OAuth providers.
5. **MySQL is source of truth** — the Google Sheet is a read-only downstream export.
6. **GAS Gmail trigger stays** — the scheduled Gmail → Google Sheet fetch is live and working. Only the Sheet → MySQL sync direction is new.
7. **`next.config.mjs` not `.ts`** — do not rename.
8. **`postcss.config.js` must exist** — do not delete.

## Database Schema

Full migration script: `mmr-webapp/db/mmr_migration_v1.sql`

### `members`
Primary member table. Matches "Membership Master → Main" Google Sheet.

| Column | Type | Notes |
|---|---|---|
| MemberID | VARCHAR(10) PK | Format: `A0001`. Generated by stored proc. |
| Status | ENUM | `'active'`, `'not active'`, `'pending'` |
| Created | DATETIME | Account creation timestamp |
| Expiration | DATETIME | Membership expiry (March 31 each year) |
| Email | VARCHAR(255) UNIQUE | **Primary login key** |
| FirstName | VARCHAR(100) | |
| LastName | VARCHAR(100) | |
| Type | ENUM | `'Individual'` or `'Family'` |
| FamilyID | VARCHAR(10) FK | → `families.FamilyID` |
| Gender | VARCHAR(20) | |
| WeChatID | VARCHAR(100) | WeChat username (for community use, not login) |
| District | VARCHAR(100) | NYC borough / region |
| MembershipFeePaid | DECIMAL(10,2) | |
| PaymentDate | DATETIME | |
| PaymentTransaction | VARCHAR(100) | |
| JoinYear | SMALLINT | |
| PhoneNumber | VARCHAR(30) | |
| LastLoginDate | DATETIME | |
| NYRRMemberID | VARCHAR(50) | For NYRR API sync |
| NYRRMemberName | VARCHAR(100) | |
| Notes | TEXT | Admin notes |
| password_hash | VARCHAR(255) NULL | bcrypt/argon2 — NULL if using OTP or social only |
| google_sub | VARCHAR(255) UNIQUE NULL | Google OAuth subject ID |
| microsoft_sub | VARCHAR(255) UNIQUE NULL | Microsoft OAuth object ID |
| apple_sub | VARCHAR(255) UNIQUE NULL | Apple OAuth sub claim |

### `member_log`
Append-only snapshot of every INSERT/UPDATE to `members`. Auto-populated by MySQL triggers.
Matches "Membership-Master-Log" sheet. All same columns as `members` plus `LogID`, `LoggingTime`, `ChangeType`, `ChangedBy`.

### `families`
| Column | Type | Notes |
|---|---|---|
| FamilyID | VARCHAR(10) PK | e.g. `B078` |
| PrimaryMemberID | VARCHAR(10) NULL | |

### `otp_tokens`
Matches "OTP" sheet.
| Column | Notes |
|---|---|
| Email | Login email |
| OTPCode | 6-digit code |
| ExpiresAt | 24h from creation |
| Used | Boolean — invalidated after first use |
| IPAddress | For rate limiting |

### `password_reset_tokens`
New table for forgot-password flow.
| Column | Notes |
|---|---|
| TokenHash | SHA-256 of token sent in email link (never store plaintext) |
| ExpiresAt | 1 hour from creation |
| Used | Single-use |

### `payment_events`
Portal payment submissions. Matches "WebApp-Events" sheet.
| Column | Notes |
|---|---|
| EventID | e.g. `EV-1772830551733-9840` |
| EventType | `'PaymentProof'` |
| MemberID | FK → members |
| Email | Denormalized for quick lookup |
| PaymentIntent | `'Individual Membership'`, `'Family Membership'`, `'Family Upgrade'` |
| Amount | 30 / 50 / 20 |
| PaymentMethod | `'Zelle'` or `'Venmo'` |
| PayerName | Name on Zelle/Venmo account |
| MemoField | Memo/note entered by member |
| Last4Digits | Optional Zelle transaction last 4 |
| Status | `'pending'`, `'approved'`, `'rejected'` |
| MatchedMessageId | FK → `gmail_transactions.MessageId` |
| ScreenshotFileId | Azure Blob Storage file reference |
| GDriveFilePath | Azure Blob URL of payment screenshot |
| OCRText | OCR result from screenshot |

### `payments`
Confirmed payment records (financial ledger). Matches "Payment-History" sheet.
| Column | Notes |
|---|---|
| PaymentID | e.g. `PY-1772856778992-9574` |
| EventID | FK → payment_events |
| MemberID | FK → members |
| TransactionReference | Zelle/Venmo transaction number |
| PeriodStart / PeriodEnd | Membership period covered |
| ProcessedBy | Who/what approved (`auto-reconcile@system` or admin email) |
| Source | `'WebApp'`, `'Admin-Created'` |

### `gmail_transactions`
Parsed Gmail payment notifications. Combines "Fetch Gmail Data → Active + Archive" sheets.
| Column | Notes |
|---|---|
| MessageId | Gmail message ID — globally unique PK |
| TransactionNumber | Zelle confirmation # or Venmo transaction ID |
| Source | `'Zelle'` or `'Venmo'` |
| WebAppID | FK → `payment_events.EventID` once matched |
| IsArchived | FALSE = Active tab, TRUE = Archive tab |

### `activity_log`
Session and action audit log. Matches "WebApp-ActivityLog" sheet.
Key `Action` values: `LOGIN_START`, `LOGIN_SUCCESS`, `PAYMENT_SUBMIT`, `PROOF_UPLOAD`, etc.

### `config`
Key-value app settings. Pre-seeded values:

| Key | Value |
|---|---|
| IndividualPrice | 30 |
| FamilyPrice | 50 |
| PaymentMethods | Zelle,Venmo |
| ReminderDaysBefore | 30 |
| MembershipRenewalYears | 1 |
