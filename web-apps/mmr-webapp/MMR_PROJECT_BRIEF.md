## Tech stack

### Frontend / App
- **Framework**: Next.js 14.2.5, App Router, TypeScript, Tailwind CSS
- **Repo**: GitHub → mmrunners/mmr-webapp (main branch auto-deploys)
- **Local dev**: `npm run dev` at `http://localhost:3000`
- **Config file**: `next.config.mjs` (NOT `.ts` — Next.js 14 does not support TypeScript config)
- **Node version**: Use Node 18 or 20 LTS (not v25 unstable)

### Hosting
- **Azure Static Web Apps** (free tier) — hosts Next.js + API routes as Azure Functions
- **Prototype static site**: Azure Blob Storage static website
  - Storage account: `mmrunnersstorage`
  - Container: `$web`
  - Live URL: `https://mmrunnersstorage.z[X].web.core.windows.net`

### Database
- **Azure Database for MySQL Flexible Server**
  - Host: `mmr-mysql.mysql.database.azure.com`
  - Database: `mmrdb`
  - User: `mmradmin`
  - SSL required
- **Current source of truth**: Google Sheet "Membership Master" (being migrated to MySQL)
- **Strategy**: MySQL is source of truth; nightly sync exports read-only roster back to Google Sheet for volunteers

### Storage
- **Azure Blob Storage**: `mmrunnersstorage`
  - Container `media` — payment proof screenshots, blog images
  - Container `$web` — static website prototype

### Email
- **Azure Communication Services** — OTP emails, membership confirmation emails

### Authentication
- Email-based OTP (no passwords), JWT session cookie (7-day), `jose` library
- Edge middleware protects `/portal/*` and `/api/members/*`

### Payments
- **NO Stripe** — Zelle and Venmo only (no transaction cost)
- Zelle handle: `treasurer@mmrunners.org`
- Venmo handle: `@MMRunners`
- QR code images: `public/images/qr-zelle.png`, `public/images/qr-venmo.png`

## Key design decisions (do not reverse without asking)
1. **No Stripe** — manual Zelle/Venmo flow per PRDv4
2. **Pending state is derived**, never stored on member row — query `payment_events` table at display time
3. **Member ID format**: `MMR-YYYY-NNNN` generated by MySQL stored procedure (atomic, no race conditions)
4. **Bilingual**: English + 中文 via `translations.ts` key map + `LanguageProvider` context + `useLang()` hook
5. **next.config.mjs** not `.ts` — critical, do not rename
6. **postcss.config.js** must exist — Tailwind won't compile without it

## Database schema highlights

### `members` table
| Column | Notes |
|---|---|
| member_id | MMR-YYYY-NNNN, generated by stored proc |
| email | unique, primary login key |
| status | 'not active' / 'active' / 'expired' / 'inactive' |
| membership_type | 'individual' / 'family' |
| expires_at | set on activation |

### `payment_events` table (PRDv4 "WebApp-Events")
| Column | Notes |
|---|---|
| event_id | EVT-YYYYMMDD-XXXXX |
| member_id | FK to members |
| email | denormalized for quick lookup |
| payment_intent | 'Individual Membership' / 'Family Membership' / 'Family Upgrade' |
| amount | 30 / 50 / 20 |
| payment_method | 'zelle' / 'venmo' |
| payer_name | name on payment account |
| payment_date | date of payment |
| memo_field | memo entered by member |
| last4_digits | optional Zelle confirmation # last 4 |
| status | 'Pending' / 'Matched' / 'Approved' / 'Rejected' |
| proof_url | Azure Blob URL of screenshot |

### `otp_codes` table
Stores 6-digit OTP codes with expiry for email login.
