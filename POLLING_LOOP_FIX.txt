POLLING INFINITE LOOP — ROOT CAUSE & FIX
═══════════════════════════════════════════════════════════════════════════════

THE BUG
───────────────────────────────────────────────────────────────────────────────

When a sync job completes, the frontend NEVER stops polling `/api/sync/status/{jobId}`.

Evidence from logs:
  2026-04-04T16:21:00 [FETCH] Job 594c20eb COMPLETE status=error, still being polled
  2026-04-04T16:21:01 [FETCH] Job 594c20eb COMPLETE status=error, still being polled
  2026-04-04T16:21:02 [FETCH] Job 594c20eb COMPLETE status=error, still being polled
  ...
  (continues indefinitely, ~1 request per second)


ROOT CAUSE
───────────────────────────────────────────────────────────────────────────────

File: mmr-admin/templates/index.html (line 1908-1924)
Function: pollJobStatus(jobId)

OLD CODE:
  const pollJobStatus = (jobId) => {
    const poll = setInterval(async () => {
      try {
        const r = await api(`/api/sync/status/${jobId}`);
        if (r.ok && r.data) {  ← PROBLEM: expects r.data
          const job = r.data;
          setJobs(...);
          if (job.status === 'done' || job.status === 'error') {
            clearInterval(poll);  ← Would stop if we got here
            setToast(...)
          }
        }
      } catch (e) { ... }
    }, 1000);
  };

The API returns: { ok: true, job: { status: 'done', ... } }
But code checks: r.ok && r.data  ← ALWAYS FALSE!

Result: The condition `r.ok && r.data` never passes
        → job never gets updated
        → clearInterval(poll) never executes
        → polling continues forever


ISSUE TIMELINE
───────────────────────────────────────────────────────────────────────────────

1. Old API endpoint returned: { ok: true, data: job }
2. Frontend code written to expect: r.ok && r.data

3. New API endpoint (api_sheets_sync_routes.py) changed response to: { ok: true, job: job }
   Reason: Matches REST API conventions, clearer naming

4. Frontend code NOT updated to match new response format
   Result: Condition `r.ok && r.data` always evaluates to false

5. Bug only manifests when:
   - New API endpoint is active (api_sheets_sync_routes.py)
   - Old endpoint is removed/disabled
   - Polling continues forever because the "stop" condition is never met


THE FIX
───────────────────────────────────────────────────────────────────────────────

File: mmr-admin/templates/index.html (line 1908-1937)

NEW CODE:
  const pollJobStatus = (jobId) => {
    const poll = setInterval(async () => {
      try {
        const r = await api(`/api/sync/status/${jobId}`);

        // Handle both old format (r.data) and new format (r.job)
        const job = r.data || r.job;  ← Support BOTH formats

        if (r.ok && job) {
          setJobs(j => ({ ...j, [jobId]: { ...j[jobId], ...job } }));

          // STOP POLLING when job completes
          if (job.status === 'done' || job.status === 'error') {
            clearInterval(poll);  ← NOW WORKS
            setToast(job.status === 'done' ? `✅ ${job.message}` : `❌ ${job.message}`);
            console.log(`[POLL-STOP] Job ${jobId} finished with status: ${job.status}`);
          }
        } else if (!r.ok) {
          // Job not found (404) or other error — stop polling
          console.warn(`[POLL-STOP] Job ${jobId} not found or error: ${r.error || 'unknown'}`);
          clearInterval(poll);  ← ALSO STOP on 404
        }
      } catch (e) {
        console.error(`[POLL-ERROR] Job ${jobId}: ${e.message}`);
        // Don't stop on network error — retry next interval
      }
    }, 1000);

    return poll; // Return interval ID for manual cleanup if needed
  };

KEY CHANGES:
1. ✅ Line 1914: "const job = r.data || r.job;" handles both response formats
2. ✅ Line 1920-1923: Same completion logic, but now actually reachable
3. ✅ Line 1925-1928: Added handling for 404/not-found errors
4. ✅ Line 1923, 1927, 1931: Added console logging for debugging


HOW TO VERIFY THE FIX
───────────────────────────────────────────────────────────────────────────────

1. Open browser DevTools (F12 → Console tab)

2. Start a sync job from the admin dashboard

3. Watch the Console logs:
   EXPECTED:
     (while running) [progress messages...]
     (once done)    [POLL-STOP] Job {id} finished with status: done
     (polling stops)

   BUG WOULD SHOW:
     (while running) [progress messages...]
     (once done)    [no POLL-STOP message]
     (polling continues forever, requests visible in Network tab)

4. In Network tab (F12 → Network):
   - Filter: status (to see API calls)
   - EXPECTED: /api/sync/status/{id} calls stop after job completes
   - BUG: /api/sync/status/{id} continues every 1 second indefinitely

5. Tail server logs:
   EXPECTED:
     [FETCH] Job {id} status=running, progress=50%
     [FETCH] Job {id} COMPLETE status=done, still being polled ← (1-2 times, then stops)

   BUG:
     [FETCH] Job {id} COMPLETE status=done, still being polled ← (100+ times)
