# Schema Export Endpoint — Quick Guide

**Updated:** 2026-04-03 | **Endpoint:** `/api/export-schema`

---

## What's New in the Updated Endpoint

The schema export endpoint now includes:

✅ **CREATE TABLE** statements (all tables, sorted)
✅ **CREATE VIEW** statements (if any views exist)
✅ **CREATE TRIGGER** statements (if any triggers defined)
✅ **Column reference comments** (V11 schema design metadata)
✅ **Timestamp** of export for audit trail

---

## How to Use (No MySQL Access Needed)

### Option 1: Browser (Easiest)
```
https://<your-mmr-admin-url>/api/export-schema
```
- Navigate directly in browser
- Click "Save" or auto-downloads as `schema_snapshot.sql`

### Option 2: curl (Offline-friendly)
```bash
curl https://<your-mmr-admin-url>/api/export-schema > db/schema_snapshot.sql
```

### Option 3: PowerShell (Windows)
```powershell
Invoke-WebRequest -Uri "https://<your-mmr-admin-url>/api/export-schema" `
  -OutFile "db/schema_snapshot.sql"
```

## Next Steps for V11 Schema Update

1. **Download the schema:**
   ```bash
   curl https://<your-mmr-admin-url>/api/export-schema > db/schema_snapshot.sql
   ```

2. **Review the file** (check if submissions table has old column names):
   ```bash
   grep -A 30 "CREATE TABLE.*submissions" db/schema_snapshot.sql
   ```

3. **If old column names present** (EventID, EventType, etc.):
   - Run MIGRATION_V11_TRIGGERS_AND_RENAME.sql on production
   - Then re-export the schema (step 1)

4. **After schema is updated**, commit:
   ```bash
   git add db/schema_snapshot.sql
   git commit -m "chore: update schema snapshot with submissions rename + triggers"
   ```

5. **Optional:** Remove this endpoint after you're done
   - Delete: `mmr-admin/api_schema.py`
   - Edit: `mmr-admin/app.py` → remove `from api_schema import schema_bp` and `app.register_blueprint(schema_bp)`

## Troubleshooting

### Error: "Missing MySQL env vars"
**Problem:** Endpoint can't find database credentials.
**Solution:** Ensure MYSQL_HOST, MYSQL_USER, MYSQL_PASSWORD are set in Azure App Settings or local .env.local

### Error: "MySQL connection failed"
**Problem:** Can't connect to Azure MySQL.
**Solution:**
- Verify credentials are correct
- Check firewall rules (Azure MySQL → allow Azure services)
- Try accessing MySQL directly: `mysql-mmr -e "SELECT 1;"`

### Error: "Unexpected error"
**Problem:** Unknown issue.
**Solution:** Check Azure App Service logs for full error stack.

## Security Note

⚠️ **This endpoint is NOT authenticated.** It returns your database schema (structure only, no data).

After exporting the schema, consider:
1. Removing this endpoint (delete api_schema.py)
2. Or adding authentication guard (add `@login_required` decorator)
3. Or restricting to certain IPs (via Azure NSG rules)

## File Format

**Content-Type:** `text/plain` (SQL)
**Filename:** `schema_snapshot.sql`
**Size:** Typically 50–150 KB (depends on # of tables/views/triggers)

## Advanced Usage

### Export to file with timestamp
```bash
TIMESTAMP=$(date +%Y%m%d_%H%M%S)
curl https://<your-mmr-admin-url>/api/export-schema > "db/schema_snapshot_${TIMESTAMP}.sql"
```

### Check what triggers are included
```bash
curl https://<your-mmr-admin-url>/api/export-schema | grep -A 5 "CREATE TRIGGER"
```

### Verify views are exported
```bash
curl https://<your-mmr-admin-url>/api/export-schema | grep -c "CREATE VIEW"
# Should return > 0 if views exist
```
