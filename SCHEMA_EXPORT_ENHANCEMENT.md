## What Was Updated

## Changes Made to api_schema.py

### 1. Enhanced `_export_via_connector()` function
**Before:** Only exported CREATE TABLE statements

**After:** Now exports in order:
1. CREATE TABLE statements (sorted by name)
2. CREATE VIEW statements (if any exist)
3. CREATE TRIGGER statements (if any exist)
4. Column reference comments (for V11 design reference)

### 2. Added `_get_timestamp()` helper
Returns UTC timestamp for audit trail (`YYYY-MM-DDTHH:MM:SS UTC`)

### 3. Updated docstring
Explains what's included, how to use, and post-export steps

## How to Use (From Your Hotel)

### Step 1: Download Latest Schema
```bash
# Via curl (works offline)
curl https://<your-mmr-admin-url>/api/export-schema > db/schema_snapshot.sql

# Or via browser
# Navigate to: https://<your-mmr-admin-url>/api/export-schema
# Click Save
```

### Step 2: Review in Your Editor
```bash
cat db/schema_snapshot.sql
# Look for:
# - "CREATE TABLE `submissions`" (formerly webapp_events)
# - Current column names (will show old EventID, EventType, etc. if not yet renamed)
# - Any existing triggers (from previous versions)
```

### Step 3: Plan Amendments
Use the schema file to see:
- Current column structure (before rename)
- Any views that need updates
- Any existing triggers (that need to be preserved or updated)

### Step 4: After Staging Migration
1. Run MIGRATION_V11_TRIGGERS_AND_RENAME.sql on staging
2. Re-export: `curl https://<your-mmr-admin-url>/api/export-schema > db/schema_snapshot.sql`
3. Review changes:
   ```bash
   # Check submissions table has new column names
   grep "SubmissionID\|SubmittedAt\|ApprovedAt" db/schema_snapshot.sql
   # Should show new names if migration successful
   ```

### Step 5: Commit
```bash
git add db/schema_snapshot.sql
git commit -m "chore: update schema snapshot with submissions rename + V11 triggers"
git push origin main
```

## Use Cases (From Hotel)

### Scenario 1: "I need to see current submissions columns"
```bash
# Download schema
curl https://<url>/api/export-schema > schema.sql

# Extract submissions table definition
grep -A 50 "CREATE TABLE.*submissions" schema.sql | head -60

# See column names, data types, indexes
```

### Scenario 2: "Are there any existing triggers?"
```bash
# Check triggers section
grep "CREATE TRIGGER" schema.sql

# Count them
grep -c "CREATE TRIGGER" schema.sql
```

### Scenario 3: "What views exist?"
```bash
grep "CREATE VIEW" schema.sql

# List them
grep "CREATE VIEW" schema.sql | sed 's/.*`\([^`]*\)`.*/\1/'
```

### Scenario 4: "Did my V11 migration work?"
```bash
# Before migration
curl https://<url>/api/export-schema | grep -i "EventID\|EventType" | head -5
# Should show old column names

# After MIGRATION_V11 runs (on production)
curl https://<url>/api/export-schema | grep -i "SubmissionID\|SubmissionType" | head -5
# Should show new column names
```

## Technical Details

### Endpoint
- **URL:** `/api/export-schema`
- **Method:** GET
- **Authentication:** None (keep it private!)
- **Response Type:** text/plain (SQL)
- **File Name:** `schema_snapshot.sql`

### Fallback Chain
1. **Try mysqldump** (if mysql-client is available locally)
2. **Fall back to mysql-connector-python** (works everywhere, including Azure)

### No Authentication Guard
⚠️ This endpoint returns schema structure (DDL only, no data), but it's unauthenticated.

**After you're done:**
- Delete `api_schema.py` and remove blueprint registration, OR
- Add `@login_required` decorator to gate it
